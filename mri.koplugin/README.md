# MRI: Mobile Reading Intelligence

MRI 是一款面向小屏 Kindle 的 EPUB 阅读助手。它只把明确的阅读范围发送给用户选择的 AI 服务，并默认阻止当前位置之后的剧透。界面和回答会跟随 KOReader 使用简体中文或英文。

## 当前功能

- 回顾当前章、前两章，或从开头到当前位置。
- 回顾默认把当前允许范围整段发送；服务明确报告上下文或请求长度超限时，自动退回最多六段摘要再合并。取消、断网和鉴权错误不会触发重复请求。
- 长按选中文字后只有一个 MRI 按钮；AI 会判断人物、地点、概念或段落并采用相应解释方式。
- 从阅读范围生成人物表、地点表和代表性高频概念表；结果随本书保存，可直接查看或手动更新。
- 资料表默认使用自动混合模式：先结合书名、作者、阅读进度、章节记忆和三段小样本；模型可靠地熟悉作品时可用已有知识补全候选项，并以本书译名和剧透边界为准。模型不熟悉或证据不足时自动扩大到六段。设置中可以开启“资料表只依据本书文字”。
- “回顾阅读”包含全书简介；关闭剧透时生成无剧透导读，开启后可以覆盖完整剧情与结局。
- 每次 AI 请求都会在后台附带书名、作者、全书进度、当前章节和章节内进度，用于控制阅读范围和剧透；回答不会复述这些位置。提到书中内容时默认自然转述，原句措辞重要时才短引用。
- 可在设置中选择短、中、长三档回答长度；所选档位会写入所有 AI 请求的总提示词，并同步调整最大输出量。
- MRI 可在详细解释前显示三行速览；人物显示背景、关系和作用，其他类型会自动使用对应字段。该功能默认开启，可在设置关闭。
- 用户主动获得一次 AI 回答后，MRI 可在后台用一次合并请求预生成人物表、地点表和概念表。前台回答不等待；缓存超过 5% 阅读进度后更新，后台失败只写运行日志。该功能默认开启，可在设置关闭。
- MRI 条目同时保留首次出现、阅读过程中的代表性出现和最近出现，适合长篇小说。
- 每本书会在本地保存最多 80 条 AI 回答缓存。相同 MRI 选词、回顾范围、全书简介或“问这本书”的相同问题，在阅读进度差不超过 5% 时直接复用；超过 5%，或切换模型、接口、剧透、回答长度或界面语言后重新生成。连续聊天仍只保存在当前会话。
- “问这本书”会明确显示当前使用已读内容还是包含后文的全书范围。
- 在单次阅读会话内连续追问，只显示最新回答。
- 中文提问框在键盘上方提供“上一字 / 选定·空格 / 下一字”按钮，用来切换和确认拼音候选，无需在输入框里操作。
- 进入下一章后可生成短回顾并立即显示；只保存最后一次自动回顾。显示行为可在菜单关闭。
- 设置中的“测试回顾速度（已读内容）”会让同一模型依次运行整段请求和当前的分段合并流程，并把输入大小、估算 token、每次请求耗时和总耗时写入运行日志。测速会真实消耗 API 配额。
- 支持 OpenAI、Anthropic、Gemini、Qwen、DeepSeek、Kimi，以及两类自定义兼容接口。

## 兼容范围

- 已在 Kindle Oasis 上实机验证 KOReader `v2025.08` 和 `v2026.07.1`。
- 当前只支持 EPUB，不处理 PDF。

## 安装

把整个 `mri.koplugin` 文件夹复制到 KOReader 的 `plugins` 目录，然后完整退出并重新启动 KOReader。若设备上仍有旧的 `aireader.koplugin`，请先保留其中的配置；项目附带的同步脚本会在首次改名时迁移旧目录。

在 macOS 上也可以直接双击项目根目录的 `同步 MRI 到 Kindle.command`。脚本会自动找到已挂载的 Kindle，将电脑端插件完整同步到设备，并校验核心文件。电脑端存在 `config.json` 时，它会作为配置来源同步 Key、模型和接口地址；缺少该文件时会保留 Kindle 上的现有配置。

进入 `MRI → AI 服务与设置` 选择服务、回答长度，控制 MRI 速览、资料表知识来源、剧透或自动回顾，也可以设置 API Key、模型和接口地址。预设地址和模型都可以覆盖。

### 在电脑上填写 API Key

先把 `mri.koplugin/config.example.json` 复制为 `mri.koplugin/config.json`，再用电脑打开 `config.json`，填写需要的 Key：

```json
{
  "api_keys": {
    "openai": "sk-...",
    "anthropic": "",
    "gemini": ""
  },
  "models": {
    "openai": "gpt-4.1-mini",
    "anthropic": "claude-haiku-4-5",
    "gemini": "gemini-2.5-flash-lite"
  },
  "endpoints": {}
}
```

`models` 中可以直接填写每个服务使用的模型名字；留空会继续使用 Kindle 设置或插件预设。电脑配置优先级最高，每次发起请求时重新读取。

安装时只需复制整个 `mri.koplugin` 文件夹。更新时请保留自己的 `config.json`。该文件已被 Git 忽略，不会进入源码提交或发布安装包；仍请避免通过截图、聊天或其他渠道分享它。

## 使用

- 阅读器主菜单的“工具”页会优先显示 `MRI`：回顾阅读、人物地点概念、问这本书，以及一行“AI 服务与设置”。
- 长按选中文字 → `MRI`：直接识别人名、地点、概念或段落并给出相应解释。
- KOReader 手势设置中可绑定 `MRI` 和 `MRI: recap`。

回答默认非流式，使用真诚、自然的书评式语气，避免排比和同义词堆叠。普通回答使用紧凑短段落。列表以“-”表示主项，以“•”表示主项下确实需要拆开的补充信息；没有第二层时不用“•”。人物、地点和概念等资料表不使用数字编号，并以空行分隔主项。输出保持纯文本，不显示其他 Markdown 标记。支持的服务会收到关闭 thinking/reasoning 的参数；不支持该参数的兼容接口会自动去掉参数重试一次。

## 隐私与安全

- API Key 以明文保存在 Kindle 本机的 `settings/mri.lua`，不会写入插件日志。
- 临时对话只在内存中，关闭书籍或重启 KOReader 后消失。
- 最后一次自动回顾、人物表、地点表、概念表、最多 200 条章节记忆及最多 80 条 AI 回答缓存保存在这本书的 KOReader 设置中。
- 三个资料表从允许的阅读范围均匀抽取最多 6 段文字，无需把整部长篇一次载入 Kindle 内存。
- 后台预生成会额外消耗一次 AI 请求；它与前台回答顺序执行，不同时发出多个请求。
- “开头到这里”在长篇中使用章节记忆和最多 6 段均匀样本，控制内存与请求大小。
- 剧透默认关闭，只发送当前位置之前或用户明确选中的文字。开启后，MRI、全书简介、问这本书和三个资料表可以发送全书样本。
- 插件不关闭 TLS 证书校验。

建议为阅读插件单独创建有限额的 API Key。不要把含有 Key 的 KOReader 设置目录提交到 Git。
